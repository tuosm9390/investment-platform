# AI 투자 예측 시스템 프롬프트 통합 및 고도화 작업 계획서

본 계획서는 `SMC_prompt.md`와 `traning_prompt.md`의 전문 트레이딩 로직을 `src/app/api/ai/predict/route.ts`에 성공적으로 통합하기 위한 구체적인 단계와 검증 방법을 정의합니다.

## 1. 개요 및 목표

- **목표**: 하드코딩된 프롬프트를 제거하고, 두 개의 전문 MD 프롬프트를 기반으로 한 기관급 분석 시스템 구축.
- **핵심 요구사항**: SMC/ICT 전략의 전문 용어(FVG, OB, MSS 등) 사용 및 시간/유동성 중심의 분석 결과 도출.

## 2. 세부 구현 단계

### 1단계: 프롬프트 로딩 유틸리티 구축
- `src/lib/` 경로에 `promptLoader.ts`를 생성하여 파일 시스템(`fs`)을 통해 외부 마크다운 파일을 읽어오는 기능을 구현합니다.
- 서버 측(`api`)에서만 실행되도록 환경을 설정합니다.

### 2단계: `route.ts` 로직 개편
- **프롬프트 통합**: `SMC_prompt.md`의 필터링 시스템과 `traning_prompt.md`의 페르소나 및 출력 형식을 결합한 최종 프롬프트를 구성합니다.
- **데이터 주입**: 현재 가격, 일봉/4시간봉 기술 지표, 심볼 정보 등을 템플릿 리터럴을 통해 주입합니다.
- **응답 스키마 확장**:
  - `recommendation`, `trend`, `confidence` 필드 유지.
  - `insights` 배열 내에 [MARKET CONTEXT], [SETUP VALIDATION], [TRADE PLAN], [EXPERT WARNING]의 내용이 포함되도록 프롬프트 가이드라인을 강화합니다.

### 3단계: AI 모델 설정 최적화
- `gemini-flash-latest` 모델의 창의성(Temperature)을 낮게 설정(0.2~0.3)하여 일관되고 분석적인 답변을 유도합니다.

### 4단계: 테스트 및 검증
- 특정 심볼(예: BTC, ETH)에 대한 API 호출 테스트를 수행합니다.
- **체크리스트**:
  - [ ] 응답 결과가 유효한 JSON 형식인가?
  - [ ] SMC/ICT 전문 용어가 정확하게 사용되었는가?
  - [ ] 손절가(Stop Loss)와 목표가(Target Price)가 기술적 구조에 기반하여 산출되었는가?
  - [ ] 신뢰도 점수가 프롬프트에서 정의한 기준에 따라 부여되었는가?

## 3. 예상 리스크 및 대응

- **프롬프트 토큰 제한**: 두 프롬프트가 다소 길어 `gemini-flash` 모델의 입력 한계를 초과할 수 있습니다. 핵심 로직 위주로 병합하여 최적화하겠습니다.
- **JSON 파싱 에러**: AI 응답이 마크다운 형식을 포함할 경우 파싱 실패 가능성이 있습니다. 정규식 처리를 강화하여 견고한 파싱 로직을 유지하겠습니다.

## 4. 향후 확장성

- **다양한 전략 지원**: 향후 `src/prompt/` 폴더에 다른 전략 파일을 추가하는 것만으로 손쉽게 분석 모델을 교체할 수 있는 구조를 지향합니다.
